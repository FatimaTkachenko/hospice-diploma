## Сравнение по времени

### Ручное тестирование

- **Полный прогон 24 проверок:** ~60 минут (с подготовкой данных, вводом, переключениями).
- **Повторный прогон:** тоже ~60 минут.
- **Риск ошибки:** высокий (человеческий фактор).

### Автоматизированное тестирование

- **Первый прогон (сборка + установка):** ~8 минут.
- **Повторный прогон:** ~4 минуты.
- **Проверок:** 7 (покрывают ключевой функционал).
- **Риск ошибки:** нет (детерминированное выполнение).

**Экономия:** ~15× быстрее при повторных прогонах.

## Найденные проблемы (автоматизация)

### BUG-001: Creation date

**Описание:** Поле `Creation date` в Control panel отображает `25.05.58730` вместо `25.05.2026`.

**Тест:** `ControlPanelTest.creationDateShouldNotContainInvalidYear`

**Скриншот:** прикреплён к Allure-отчёту (в `allure-results.zip`).

**Issue:** [#1](https://github.com/FatimaTkachenko/hospice-diploma/issues/1)

### BUG-002: Создание новости

**Описание:** Невозможно создать новость. Сервер возвращает **500 StackOverflowError**. Причина: `convertNewsCategory` в `Utils.kt` использует категории, **несовпадающие с UI** → `newsCategoryId = 0` → сервер отклоняет.

**Тест:** `CreateNewsTest.createNewsFailsDueToCategoryBug`

**Скриншот:** прикреплён к Allure-отчёту.

**Issue:** [#2](https://github.com/FatimaTkachenko/hospice-diploma/issues/2)

## Выводы

1. **Автоматизация** экономит **время** при повторных прогонах (~15×).
2. **Ручное тестирование** необходимо для **исследовательских** проверок.
3. **Автотесты** стабильны, детерминированы, документируют баги в виде `FAIL`-тестов.
4. **Allure** даёт **наглядный отчёт** с шагами и скриншотами.
5. **2 бага** (BUG-001, BUG-002) зафиксированы в **GitHub Issues**.
