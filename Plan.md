# План проверки и автоматизации приложения «Мобильный хоспис»

## 1. Цели проекта

Закрепить знания и навыки по автоматизации тестирования мобильных приложений.
В результате выполнения:
- проведено ручное тестирование мобильного приложения «Мобильный хоспис»;
- составлен чек-лист для проверки приложения;
- составлены тест-кейсы для проверки приложения;
- автоматизирована проверка тест-кейсов по чек-листу;
- составлены отчёты о тестировании.

## 2. Описание приложения

Приложение даёт функционал по работе с новостями хосписа и включает в себя:
- информацию о новостях и функционал для работы с ними;
- тематические цитаты.

## 3. Границы приложения (что входит в тестирование)

### 3.1. Входит в тестирование
- Авторизация в приложении.
- Просмотр списка новостей.
- Создание новости.
- Редактирование новости.
- Удаление новости.
- Фильтрация/сортировка новостей (если реализовано).
- Просмотр тематических цитат (раздел «О приложении» / цитаты).
- Выход из приложения (Logout).

### 3.2. Не входит в тестирование
- Серверная часть (backend).
- Производительность и нагрузка.
- Безопасность (пентест).
- Локализация на другие языки.

## 4. Типы тестирования

| Тип | Что проверяем |
|-----|---------------|
| Функциональное | Авторизация, CRUD новостей, цитаты, навигация |
| UI/UX | Корректность отображения элементов, верстка |
| Негативное | Неверный логин/пароль, пустые поля, граничные значения |
| Регрессионное | Повторная проверка после изменений |
| Дымовое (smoke) | Ключевой функционал при первом запуске |

## 5. Этапы работы

### Этап 1. Ручное тестирование
1. Установка приложения на эмулятор/устройство.
2. Авторизация (`login2` / `password2`).
3. Составление чек-листа (`docs/Check.csv`).
4. Прохождение чек-листа вручную с отметками pass/fail.
5. Составление тест-кейсов (`docs/Cases.csv`).
6. Отметка покрытия тест-кейсов автотестами.

### Этап 2. Автоматизация
1. Настройка проекта под UI-тесты:
   - добавление библиотек (Espresso, UI Automator, JUnit, Allure);
   - создание директории `androidTest`;
   - настройка тестового класса;
   - флаг `android.injected.androidTest.leaveApksInstalledAfterRun=true` в `gradle.properties`.
2. Написание UI-тестов по чек-листу.
3. Каждое действие завершается проверкой.

### Этап 3. Отчётность
1. Подключение Allure:
   - зависимости;
   - права приложению.
2. Разметка тестов:
   - названия функциональностей;
   - описания;
   - шаги;
   - скриншоты при падении.
3. Выгрузка отчётов с мобильных устройств.
4. Проверка работоспособности.
5. Упаковка в `allure-results.zip`.

## 7. Критерии готовности проекта

- Проект собирается, тесты запускаются без дополнительных манипуляций.
- Проект работает на Android API 36.
- В проекте есть UI-тесты.
- Понятные названия тестов, методов и элементов.
- Нет явных изъянов в архитектуре, корректный code style.
